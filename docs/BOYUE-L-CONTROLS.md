# 博越 L 方控与蓝牙音乐：首批迁移

本批实现 OneOS 回退、按键标准化与去重，以及原车蓝牙音乐模式下的媒体控制和焦点归属。

## 服务选择

每次连接优先尝试 `com.geely.inputservice.InputService`。绑定被拒绝、注册失败、服务断开或 3 秒内注册尚未完成时，先释放当前绑定，再尝试 `com.geely.service.oneosapi.OneOSApiService`。两者均失败后，间隔 3 秒重新从直连服务开始。

OneOS 使用服务管理器的 `getService(8)` 取得输入接口，复用现有 `IInputManager` / `IInputListener` AIDL。原车蓝牙模式只订阅语音键；CarPlay 音频模式下，OneOS 使用参考实现的订阅表，解码器只保留媒体键和 Siri 长按。其他按键在记录日志前被过滤。

服务注册成功后持续使用当前后端。车辆尚未产生按键时保持监听；“绑定成功但没有事件”需要结合具体固件日志判断。

## 按键与音源归属

- 支持播放暂停 `85 / 200085`、下一曲 `87 / 200087 / 110005 / 210005`、上一曲 `88 / 200088 / 110006 / 210006`。
- 原始按下事件、别名重复事件及后续短按手势共用解码状态；匹配的跨来源媒体命令使用 120 ms 去重窗口。
- Siri 保留长按触发；语音短按交给原车。
- 吉利 CarPlay 音乐流建立后取得媒体控制资格，音乐暂停期间保留该资格。
- “通过车辆蓝牙播放 CarPlay 音频”开启时，音乐控制和音乐焦点交给原车。DiPlay 保留 Siri。该模式将全部音频交给蓝牙，初始化资源请求仅包含屏幕，音频流 SETUP 按同一配置拒绝。
- 吉利 CarPlay 音频模式下，启用渲染器音频焦点时，由渲染器负责焦点；媒体键模块使用同一会话的策略。已有“禁用媒体按键音频焦点”设置继续有效。

这些策略在连接创建时固定，设置变更按现有界面的重连方式应用。窗口按键、无障碍重映射、媒体会话和吉利服务回调共同遵守归属和去重规则。旧控制器及旧服务的延迟事件按归属丢弃。

## 车机使用

使用原车蓝牙播放音乐时，在 **设置 → 高级 → 视频与音频** 开启“通过车辆蓝牙播放 CarPlay 音频”，重新连接，并在 iPhone 选择原车蓝牙输出、车机选择蓝牙音乐音源。音乐、导航和通话继续按该已有模式走蓝牙。

诊断报告的 `Wheel keys:` 记录包括：

- `media control bluetoothAudio=... geely=... manageFocus=...`：本次连接的控制策略。
- `geely input backend=DIRECT/ONE_OS ...`：绑定、注册、回退及回调来源。
- `media key skipped ... awaitingMedia=...`：媒体控制归属判断。
- `media key duplicate ...`：跨来源去重结果。
- `geely wheel Siri requested=...`：Siri 请求结果。

## 验收状态与后续范围

本批增加了解码、服务回退与释放、音乐归属和旧连接事件隔离的回归用例；执行状态为待运行。本地测试、构建、lint 和车机操作依用户明确要求执行。

2026-10-19 追加：用户反馈开启车辆蓝牙音频后，首次触屏播放仍立即暂停；操作一次方向盘媒体键后，触屏播放恢复。源码中该模式仍在 `/info.modes.resources` 请求主音频资源，同时普通音频 SETUP 仍可进入渲染器。本次使初始化资源声明与音频能力开关一致，并将 type 100/101/102 音频流接收入口纳入该开关；type 103 延续已有门控。回归用例覆盖两种模式的初始资源声明及混合屏幕/音频 SETUP，执行状态为待运行。

上述协议冲突与首次播放的关联属于待车机确认的假设。新会话的诊断日志增加 `airplay /info modes=...`。停车验收时，先重新连接 CarPlay，保持车机蓝牙音乐音源，在操作方向盘之前直接触屏播放，再确认方控操作及再次重连后的首次播放。结合故障时刻日志确认原车音源、A2DP 和 AVRCP 状态。

资源请求的含义参考 [Apple：Developing CarPlay Systems, Part 2](https://developer.apple.com/videos/play/wwdc2016/723/)，其中说明了 `mainAudio` 的所有权和 `changeModes` 的资源请求语义。

停车验收顺序建议：原车蓝牙模式下从 CarPlay 与 iPhone 分别播放；方控切歌和播放暂停；CarPlay 音频模式的首次播放、连续暂停再播放；Siri 长按；断开重连后重复以上操作。保存故障时刻对应的诊断报告，用实际音源、播放状态和按键来源确认效果。

后续独立评估原车音频 usage/source、导航物理输出、Opus 下行软件回退及通话结束恢复。它们各自保留单独的迁移与车辆验收范围。
